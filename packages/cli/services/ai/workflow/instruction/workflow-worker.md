# Workflow Builder

Build semantic operations for the supplied workflow plan. Return JSON only:

`{"operations":[]}`

## Allowed operations

- `{"op":"create_node","node":{"ref":"new_step","nodeKey":"action:email","title":"...","description":"...","config":{},"afterNodeRef":"form_trigger"}}`
- `{"op":"remove_node","nodeRef":"existing_ref"}`
- `{"op":"update_node","nodeRef":"existing_ref","updates":{"title":"...","config":{"field":"value"}}}`
- `{"op":"connect","from":{"nodeRef":"form_trigger","handle":null},"to":{"nodeRef":"new_step","handle":null}}`
- `{"op":"disconnect","from":{"nodeRef":"existing_ref","handle":null},"to":{"nodeRef":"another_existing_ref","handle":null}}`
- `{"op":"insert_between","connection":{"from":{"nodeRef":"existing_ref","handle":null},"to":{"nodeRef":"another_existing_ref","handle":null}},"node":{"ref":"new_step","nodeKey":"action:email","title":"...","config":{}},"inputHandle":null,"outputHandle":null}`
- `{"op":"insert_after_route","from":{"nodeRef":"existing_ref","handle":"approved"},"beforeNodeRef":"another_existing_ref","node":{"ref":"new_step","nodeKey":"action:googleSheets","title":"...","config":{}},"inputHandle":null,"outputHandle":null}`
- `{"op":"add_condition_branch","from":{"nodeRef":"existing_ref","handle":"approved"},"condition":{"title":"Attendance is Online","config":{"valueA":{"$binding":"form_field_2"},"operator":"equals","valueB":"Online"}},"whenTrue":{"nodeKey":"action:email","title":"Send joining instructions","config":{}},"whenFalse":{"nodeKey":"action:email","title":"Send venue instructions","config":{}}}`
- `{"op":"add_condition_branch","from":{"nodeRef":"existing_ref","handle":"outputData"},"condition":{"title":"Rating is low","config":{"valueA":{"$binding":"form_field_2"},"operator":"less_than_or_equal","valueB":3}},"whenTrue":{"nodeKey":"action:email","title":"Notify support","config":{}},"whenFalse":null}` (a null route ends that path; use the exact output handle from the supplied node spec)
- `{"op":"add_switch_routes","from":{"nodeRef":"existing_ref","handle":"approved"},"switch":{"title":"Route attendance","config":{"valueToTest":{"$binding":"form_field_2"}}},"cases":[{"value":"Online","action":{"nodeKey":"action:email","title":"Send joining instructions","config":{}}},{"value":"Physical","action":{"nodeKey":"action:email","title":"Send venue instructions","config":{}}}],"otherwise":{"nodeKey":"action:email","title":"Send hybrid instructions","config":{}}}`
- `{"op":"add_error_handler","connection":{"from":{"nodeRef":"request_api","handle":"outputData"},"to":{"nodeRef":"save_result","handle":"triggerData"}},"handler":{"title":"Handle API error","config":{}},"whenError":{"nodeKey":"action:email","title":"Alert team","config":{}}}`
- `{"op":"add_approval_gate","connection":{"from":{"nodeRef":"form_trigger","handle":"triggerData"},"to":{"nodeRef":"save_response","handle":"triggerData"}},"approval":{"title":"Review response","config":{"title":"Review required","instructions":"Approve to save this response."}},"whenRejected":{"nodeKey":"action:email","title":"Send rejection notice","config":{}}}`
- `{"op":"add_approval_gate","from":{"nodeRef":"notify_support","handle":"outputData"},"approval":{"title":"Review compensation offer","config":{"title":"Review compensation offer","instructions":"Approve before sending the offer."}},"whenApproved":{"nodeKey":"action:email","title":"Send compensation offer","config":{}},"whenRejected":null}` (a new route uses `from` plus an explicit approved action)
- `{"op":"move_approval_gate","approvalNodeRef":"n4","connection":{"from":{"nodeRef":"check_attendance","handle":"false"},"to":{"nodeRef":"send_venue","handle":"event"}},"approvalUpdates":{"title":"Review before venue instructions","config":{"title":"Review before venue instructions"}}}`
- `{"op":"join_branches","branches":[{"from":{"nodeRef":"send_online","handle":"outputData"}},{"from":{"nodeRef":"send_venue","handle":"outputData"}}],"merge":{"title":"Join notifications","config":{"mergeMode":"object"}},"continueWith":{"nodeKey":"action:logger","title":"Log completion","config":{}}}`

## Rules

1. Satisfy every planner requirement and make no unrelated change.
2. Use exact node refs only for nodes already shown in the edit view, plus exact node keys, config names, and connection handles from the supplied specifications. For semantic control-flow operations, omit new node `ref` values when no later operation needs to identify the new outcome. If a later operation must connect from or read an ordinary outcome, give that outcome a unique ref such as `summarize_feedback`; the server remaps it to a collision-free compiler ref and internal ID.
3. Never output database node IDs or edge IDs. The server generates internal IDs.
4. Preserve existing configuration unless a requirement changes it.
5. Use only exact account resource values supplied by the server. Every `resource-select` value must be the literal resource ID shown in Account Resources, never its label or an object. The only exception is a Google Sheet declared in Resource Changes: set its `spreadsheetId` to `{ "$provision": "the_resource_ref" }`; set `range` to that resource change's `sheetTitle` at `A1` (for example `'Responses'!A1`). Promptly canonicalizes this range and replaces it with the exact tab returned by Google when the proposal is applied. For a form-submission trigger, `formId` must be the literal attached form ID or form option value, never `$provision`. Never invent an ID.
6. Produce one connected acyclic graph with exactly one trigger. Use explicit branch handles. Every connection handle must exactly match an `isConnection` input or output in the supplied node spec; never invent or assume generic names such as `done` or `event`. In production, a single-output action commonly uses `outputData`, a form trigger commonly uses `triggerData`, and a single-input action commonly uses `triggerData`, but the supplied spec is authoritative.
7. For submitted form values and metadata, use only a `fieldBindings[].key` from Attached Form Context. Use `{ "$binding": "form_field_1" }` for a complete value, or `{ "$template": ["Hi ", { "$binding": "form_field_2" }] }` for mixed text. `submission_submitted_at` and `submission_response_id` are available for spreadsheet rows. For data produced by an upstream node, use a canonical reference with that node's worker ref, for example `{ "$expr": "reference", "v": 1, "nodeId": "summarize_feedback", "path": ["response"] }`; use a `$template` when literal text and an upstream output must be mixed. Use only a non-connection output declared by the node spec. These references are valid in inputs marked `workflow-expression`, including `ai:aiTask.prompt`; inputs marked `node-template` must contain plain text. For an AI Task, a literal instruction may be paired with its connected input, which the node includes automatically. Never write a form field ID, database node ID, legacy double-brace reference, `${...}` interpolation, `steps.*` path, or `triggerData.*` path. If one appears in the existing workflow or a previous invalid response, replace it with the appropriate structured binding or upstream reference.
8. Control-flow topology is compiler-owned. Never create or insert `logic:condition`, `logic:switch`, `logic:catchError`, `logic:merge`, or `logic:approval` with `create_node`, `insert_between`, or `insert_after_route`.
9. For owner approval before an existing step, use exactly one `add_approval_gate` with `connection.from` and `connection.to`. It preserves the existing connection on `approved`. Omit `whenRejected` entirely unless the request explicitly requires an action after rejection; without it, a rejected run ends without continuing. For a new approval route, use `from` plus exactly one ordinary `whenApproved` action; the server connects `from → Approval → approved action`. Set `whenRejected: null` when rejection should end that route. Do not configure an external approver. To narrow or move an existing Approval to a different existing branch, use exactly one `move_approval_gate` with the exact existing Approval ref and connection. Set `approvalUpdates` when its label or instructions need to describe the new route. Do not remove and reconnect an Approval manually; the compiler preserves its rejected route.
10. For a new if/otherwise, true/false, or conditional split, use exactly one `add_condition_branch`. Its `from.handle` is the existing source route (for example an Approval node's `approved`), never `true` or `false`. The server creates `Condition.input1`, `Condition.true`, and `Condition.false` connections itself and retains the source route's existing destinations. Set one outcome to `null` when that route should end; at least one outcome must be an ordinary action.
11. For `add_condition_branch`, use a form binding such as `{ "$binding": "form_field_2" }` for `condition.config.valueA`. Supply `operator`, `valueB` unless the operator is `exists`, `empty`, `truthy`, or `falsy`. Each outcome is an ordinary node definition with a config object; the server owns all new refs and ports.
12. For a two-case router plus a default, use `add_switch_routes`. Supply one or two cases and an `otherwise` action. The compiler assigns the fixed `branchA`, `branchB`, and `default` handles, so never invent a route handle.
13. To handle a step failure, use `add_error_handler` with one exact existing connection. The compiler replaces that connection with `Catch Error.successPath`, binds the handler to the source step, and creates `errorPath` for `whenError`.
14. To join two or more branch tails, use `join_branches`. Supply the branch source routes, one Merge definition, and one ordinary `continueWith` action. The compiler owns Merge's shared input and output connections.
15. When adding a non-control step to an existing branch, prefer `insert_after_route`. Give the source node and branch handle; include `beforeNodeRef` only when that branch has more than one destination. Do not manually disconnect and reconnect an existing edge for this case.
16. If the plan has capability `per_submission_spreadsheet`, add `action:googleSheetsCreate` after approval and before `action:googleSheets` append. Do not add a Google Sheet Resource Change: that would create only one sheet at proposal apply time. Configure the create step title with the supplied form binding for `submission_response_id`; the server wires its runtime output to the append step and supplies the response headers.
17. If Form Response Sheet Destination is `provision_once` or `existing`, never add `action:googleSheetsCreate`. A Resource Change creates one Sheet only when the user applies the proposal; connect the form or approval route directly to `action:googleSheets` append instead.
18. When a Linear Blueprint is supplied, preserve its step order, refs, and exact node keys. It is a server-validated fallback contract, not a suggestion to rename or replace.
19. When `Resolved Form Workflow Contracts` supplies `rating`, `respondentEmail`, `compensationRecipient`, or `supportRecipient`, treat those values as authoritative. Use `rating` for the rating condition, `respondentEmail` or `compensationRecipient` for the compensation or respondent confirmation message as specified, and `supportRecipient` for support notifications. Never substitute the workspace owner, an invented support alias, `triggerData`, `inputData`, or an arbitrary form field. For an AI summary, use `ai:aiTask` with `taskType: "summarize"`, keep its prompt literal, connect its `outputData` to the next action, and reference its non-connection `response` output in the downstream message field.
